# REF019 · software-not-found

**Linked repository or package not found** · 链接的代码仓库或软件包不存在

| | |
|---|---|
| Severity · 严重度 | info · 提示 |
| Fix · 修复 | none · 无 |

## English

Message:

    '{key}' links to {name} on {registry}, which {registry} does not have. Check the link: the project may have been renamed, moved or made private.

**What it checks.** The entry links to a GitHub repository, a PyPI or CRAN package or an OpenML dataset, and that registry answers it does not exist. Asked only when nothing else found the reference. Hugging Face is never reported: it answers the same for a repository that does not exist and for a private one.

**When it can be wrong.** A repository made private or deleted after a move. A refused or rate-limited request is never read as "not found".

**What to do.** Update the link to where the project lives now, or cite an archived release (Zenodo, Software Heritage).

To silence it for one entry once you have checked it, put a comment above the entry:

    % preflight: ignore[REF019] reason="..."

To turn it off for the whole project: `ignore-rules = ["REF019"]` in the project's settings.

## 中文

消息：

    '{key}' 链接到 {registry} 上的 {name}，但 {registry} 没有它。请检查链接：项目可能已改名、迁移或设为私有。

**检查什么。** 条目链接到 GitHub 仓库、PyPI 或 CRAN 软件包或 OpenML 数据集，而对应平台答复它不存在。只在其他来源都找不到该文献时才查询。Hugging Face 从不报此规则：仓库不存在和设为私有时，它的答复相同。

**什么时候可能误报。** 仓库被设为私有，或迁移后被删除。被拒绝或受限流的请求不会被当作“不存在”。

**怎么处理。** 把链接改为项目现在的地址，或引用其存档版本（Zenodo、Software Heritage）。

核对之后，如需对某个条目消除此规则，在条目上方加注释：

    % preflight: ignore[REF019] reason="..."

对整个项目关闭此规则：在项目设置中写 `ignore-rules = ["REF019"]`。
