**Entry key defined twice** · 条目键重复定义

| | |
|---|---|
| Severity · 严重度 | error · 错误 |
| Fix · 修复 | none · 无 |

## English

Message:

    Entry key '{key}' is already defined at line {first_line}; BibTeX ignores this one.

**What it checks.** The same entry key defined twice, in one `.bib` file or in two. BibTeX keeps the first and ignores the other, so a citation may print another work than the one you edited.

**When it can be wrong.** Two bibliographies that are never loaded together (one per build) share keys legitimately.

**What to do.** Delete one copy, or rename it and update the citations that meant it. When the copies differ, keep the one `check` verifies.

To silence it for one entry once you have checked it, put a comment above the entry:

    % preflight: ignore[CIT002] reason="..."

To turn it off for the whole project: `ignore-rules = ["CIT002"]` in the project's settings.

## 中文

消息：

    条目键 '{key}' 已在第 {first_line} 行定义；BibTeX 会忽略这一条。

**检查什么。** 同一个条目键被定义了两次（在同一个或两个 `.bib` 文件中）。BibTeX 只保留第一个、忽略另一个，所以引用印出的可能不是你修改过的那一条。

**什么时候可能误报。** 两个从不同时加载的参考文献文件（各用于一种编译）共用键名是正常的。

**怎么处理。** 删掉其中一份，或给它改名并更新原本指向它的引用。两份内容不同时，保留 `check` 核实通过的那份。

核对之后，如需对某个条目消除此规则，在条目上方加注释：

    % preflight: ignore[CIT002] reason="..."

对整个项目关闭此规则：在项目设置中写 `ignore-rules = ["CIT002"]`。
