# REF017 · malformed-identifier

**Identifier written incorrectly** · 标识符写法错误

| | |
|---|---|
| Severity · 严重度 | warning · 警告 |
| Fix · 修复 | `bib fix` (the default, safe level) · `bib fix`（默认的 safe 级别） |

## English

Message:

    The {field} of '{key}' {problem}: '{value}'. Write it as: {suggestion}

**What it checks.** An identifier written so that links break: LaTeX escapes or braces in a DOI (`10.1162/tacl\_a\_00276`), a URL or `doi:` prefix in the `doi` field, an arXiv DOI with a version suffix, an arXiv ID with its subject class.

**When it can be wrong.** No case is known. If you meet one, please report it: false positives are the bugs we most want to hear about.

**What to do.** `bib fix` corrects it at its safe level. A value that cannot be corrected (not an identifier at all) is left for you.

To silence it for one entry once you have checked it, put a comment above the entry:

    % preflight: ignore[REF017] reason="..."

To turn it off for the whole project: `ignore-rules = ["REF017"]` in the project's settings.

## 中文

消息：

    条目 '{key}' 的 {field} {problem}：'{value}'。应写为：{suggestion}

**检查什么。** 标识符的写法会让链接失效：DOI 中的 LaTeX 转义或花括号（`10.1162/tacl\_a\_00276`）、`doi` 字段带着网址或 `doi:` 前缀、arXiv 的 DOI 带版本号后缀、arXiv 编号带着学科分类。

**什么时候可能误报。** 目前没有已知的情形。如果遇到，请提交 issue：误报是我们最想知道的问题。

**怎么处理。** `bib fix` 在 safe 级别会改正它。无法改正的值（根本不是标识符）留给你处理。

核对之后，如需对某个条目消除此规则，在条目上方加注释：

    % preflight: ignore[REF017] reason="..."

对整个项目关闭此规则：在项目设置中写 `ignore-rules = ["REF017"]`。
