# REF001 · identifier-conflict

**Identifier points to a different work** · 标识符指向另一篇作品

| | |
|---|---|
| Severity · 严重度 | error · 错误 |
| Fix · 修复 | `bib fix --level unsafe`: review the diff before applying it · `bib fix --level unsafe`：应用前请先检查差异 |

## English

Message:

    The {field} of '{key}' ({identifier}) resolves to a different work in {source}: "{found_title}" ({found_authors}, {found_year}).

**What it checks.** The entry's DOI, arXiv ID, PMID or PMCID resolves to a record whose title and authors are another work's, and no other source confirms the identifier for this entry. Typical of a pasted wrong DOI, and of invented references, which often borrow a real identifier.

**When it can be wrong.** A registry's record can itself be wrong (a DOI deposited with another work's metadata). A book's DOI given for one of its chapters is accepted when the `booktitle` names the book.

**What to do.** Open the identifier and compare. `bib fix --level unsafe` removes it; `paper-preflight bib fetch --title "..."` finds the right one.

To silence it for one entry once you have checked it, put a comment above the entry:

    % preflight: ignore[REF001] reason="..."

To turn it off for the whole project: `ignore-rules = ["REF001"]` in the project's settings.

## 中文

消息：

    条目 '{key}' 的 {field}（{identifier}）在 {source} 中指向另一篇作品："{found_title}"（{found_authors}，{found_year}）。

**检查什么。** 条目的 DOI、arXiv 编号、PMID 或 PMCID 指向的记录，标题和作者都属于另一篇作品，且没有其他来源能证实该标识符属于这个条目。常见于复制错的 DOI，也常见于编造的文献——它们往往借用真实存在的标识符。

**什么时候可能误报。** 登记机构的记录本身也可能有误（DOI 登记时填了另一篇作品的元数据）。为书中某一章给出整本书的 DOI 时，只要 `booktitle` 写的就是这本书，就不会报告。

**怎么处理。** 打开该标识符的页面核对。`bib fix --level unsafe` 会删除它；`paper-preflight bib fetch --title "..."` 可以找到正确的标识符。

核对之后，如需对某个条目消除此规则，在条目上方加注释：

    % preflight: ignore[REF001] reason="..."

对整个项目关闭此规则：在项目设置中写 `ignore-rules = ["REF001"]`。
