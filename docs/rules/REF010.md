# REF010 · authors-disjoint

**Author list is entirely different** · 作者列表完全不同

| | |
|---|---|
| Severity · 严重度 | error · 错误 |
| Fix · 修复 | `bib fix --level unsafe`: review the diff before applying it · `bib fix --level unsafe`：应用前请先检查差异 |

## English

Message:

    None of the authors of '{key}' appear on the matching record in {source} ({found_authors}).

**What it checks.** The work was identified, by its identifier or an unambiguous title match, but none of the entry's authors is on the record. Typical of invented references, which pair a real title with made-up names.

**When it can be wrong.** Names transliterated very differently, an organisation as author, or a record that lists the editors. Records of Semantic Scholar, Open Library and the software registries are not compared.

**What to do.** Compare with the work's page. `bib fix --level unsafe` writes the record's authors.

To silence it for one entry once you have checked it, put a comment above the entry:

    % preflight: ignore[REF010] reason="..."

To turn it off for the whole project: `ignore-rules = ["REF010"]` in the project's settings.

## 中文

消息：

    条目 '{key}' 的作者无一出现在 {source} 的匹配记录中（记录作者：{found_authors}）。

**检查什么。** 已经通过标识符或无歧义的标题匹配确定了作品，但条目中的作者没有一位出现在记录里。常见于编造的文献：真实的标题配上虚构的作者。

**什么时候可能误报。** 音译差别很大的姓名、以机构为作者，或记录列的是编者。Semantic Scholar、Open Library 和软件平台的记录不参与作者比对。

**怎么处理。** 对照作品页面核对。`bib fix --level unsafe` 会按记录写入作者。

核对之后，如需对某个条目消除此规则，在条目上方加注释：

    % preflight: ignore[REF010] reason="..."

对整个项目关闭此规则：在项目设置中写 `ignore-rules = ["REF010"]`。
