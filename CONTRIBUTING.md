# Contributing to paper-preflight

Thanks for your interest! The project is in its 0.x releases, on the way to a stable 1.0, so
please open an issue before starting larger changes.

## Development setup

```bash
# requires uv (https://docs.astral.sh/uv/)
uv sync
uv run pytest
uv run ruff check && uv run ruff format --check
uv run mypy
uv run pre-commit install
```

## Ground rules

1. **No LLM in the verdict path.** Verdicts must be reproducible from recorded source
   responses. No bibliographic field may be generated by a language model.
2. **Abstain rather than guess.** If a source is unavailable (rate limit, bot challenge,
   timeout, HTML instead of JSON), the affected references become "cannot determine",
   never "not found".
3. **Every network call goes through a source adapter** with rate limiting and caching.
   Never scrape sites that forbid automated access (Google Scholar, CNKI/Wanfang/VIP search
   pages, paywalled publisher pages) and never try to bypass bot challenges.
4. **Licenses.** Runtime dependencies must be MIT/BSD/Apache-2.0/ISC/MPL-2.0/PSF licensed.
   Adapted code must be permissively licensed and recorded in `THIRD_PARTY_NOTICES.md`.
5. **Test fixtures.** Recorded API responses may only come from sources whose data can be
   redistributed (Crossref without abstracts, OpenAlex, DataCite, arXiv metadata, dblp).
   Never commit Semantic Scholar responses or full texts.
6. **Bilingual messages.** User-visible strings need English and Simplified Chinese versions.
7. **Fabricated test data uses fictional author names**, never real people.

## Reporting false positives

False positives are the bugs we care about most. Please use the "False positive" issue
template and include the BibTeX entry and the output of `paper-preflight explain <finding-id>`.

## Commit messages

Use [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:`, …).
